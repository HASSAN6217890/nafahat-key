## ما اختُبر
- البناء: GitHub Actions يشغّل Java 17 وAndroid SDK 35 وGradle/AGP المعتمد.
- لا صلاحيات إضافية في AndroidManifest.
- اختبارات Java مستقلة لترتيب الأحرف والتباينات في ملفات واتساب.
- اختبارات Python للتحقق من الثوابت في المصدر والخصوصية.
- حزمة الكلمات تولَّد ضمن CI، ولا تحتاج شبكة عند عمل الكيبورد.

## ما لم يُختبر على هاتف
- زمن استجابة اللمس المتداخل، الاحتفاظ بالحرف عند الانزلاق، المسح المتسارع.
- معاينة الفقاعة فوق الكيبورد عبر onComputeInsets على أجهزة مختلفة.
- الكتابة في واتساب وإنستغرام وحقول كلمات المرور والبريد.
- استمرارية بيانات 0.2 عند التحديث، وتوقيع Release عند وجود أسرار.
- دقة التصحيح الآلي في سياق عربي/شامي حقيقي، وتحمل القاموس على هواتف متواضعة.

## مخاطر تشغيلية
1. المستودع ظهر عبر GitHub API بأنه public وليس private؛ لا تضع فيه أسراراً.
2. سير العمل القديم على main ينشر Debug APK إلى apk-builds بالقوة. إن استُخدم الفرع نفسه لاحقاً لـRelease موقّع، فقد يُستبدل APK الموقع عند أي بناء من main. يلزم تنسيق مع الفريق المسؤول عن main قبل اعتماد رابط توزيع ثابت.
3. لا يتم نشر Release موقّع إلا بعد ضبط NAFAHATKEY_KEYSTORE_B64 وNAFAHATKEY_STORE_PASSWORD وNAFAHATKEY_KEY_ALIAS وNAFAHATKEY_KEY_PASSWORD.
4. الانتقال من توقيع v0.2 المختلف قد يتطلب إزالة نسخة سابقة. **إزالة التطبيق تمحو SharedPreferences القديمة، فلا يمكن للهجرة التلقائية قراءتها بعد الإزالة.** لا تُزَل النسخة القديمة قبل تهيئة وسيلة تصدير أو نقل موثوقة لبيانات 0.2 (الإصدار القديم لا يملك تصديراً مضموناً). الهجرة المكتوبة في LibraryDb تعمل حصراً عندما تبقى بيانات التطبيق متاحة، أي مع تحديث بتوقيع متوافق أو عبر آلية نقل مُنسَّقة.

## ضابط الدمج
لا يُدمج هذا الفرع إلى main قبل اجتياز قائمة اختبارات هاتف حقيقي وتأكيد استيراد النصوص واختبار الإصدار الموقَّع. يجب إصلاح البنود الجزئية أو قبول تأجيلها صراحة.
